Jaunty

A high-performance micro-ORM for .NET that executes SQL and maps results to objects with strict type safety.

Get Started View API

New to Jaunty?

Start with the Quick Start guide to learn the basics in 5 minutes.

Features

High Performance

Compiled expression trees and metadata caching for minimal overhead. Zero reflection at query execution time.

Strict by Default

Catches mapping errors at development time. All entity properties must have matching columns or an exception is thrown.

Zero Dependencies

No external libraries required. Works with any ADO.NET provider (SQLite, SQL Server, PostgreSQL, MySQL).

Full Async Support

All methods have async counterparts with proper CancellationToken support and ConfigureAwait(false).

Flexible Mapping

Choose between strict mapping (default) or partial mapping. Support for custom mappers via IMapped<T>.

Multiple Result Sets

QueryMultiple and GridReader for handling multiple result sets in a single database round-trip.

Quick Example

public class Product
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
}

// Query with strict mapping
var products = connection.Query<Product>(
    "SELECT * FROM products WHERE category_id = @CategoryId",
    new { CategoryId = 5 });

// Insert and get identity
var newProduct = new Product { Name = "Widget", Price = 19.99m };
var id = connection.Insert(newProduct);

Installation

dotnet add package Beparey.Jaunty

Jaunty targets both netstandard2.0 and net8.0 for broad compatibility and modern optimizations.

Why Jaunty?

Unlike other micro-ORMs, Jaunty uses strict mapping by default. This means all entity properties must have matching columns in the result set, or an exception is thrown immediately. This catches bugs at development time instead of production.

ℹ Partial Mapping Available

Need to select only specific columns? Use QueryPartial<T> for partial mapping where only existing columns are mapped.
