Global Configuration

Jaunty provides global configuration options through the JauntyConfig class. Configuration should be set at application startup before executing any queries.

JauntyConfig Properties

public static class JauntyConfig
{
    // Custom resolver for schema names
    public static Func<Type, string?> SchemaNameResolver { get; set; }

    // Custom resolver for table names
    public static Func<Type, string?> TableNameResolver { get; set; }

    // Custom resolver for column names
    public static Func<string, string?> ColumnNameResolver { get; set; }

    // Reset all configuration to defaults
    public static void Reset();
}

Setting Configuration

// At application startup
JauntyConfig.ColumnNameResolver = NamingConvention.ToSnakeCase;  // ProductName -> product_name
JauntyConfig.TableNameResolver = NamingConvention.SnakeCasePluralTable;  // Product -> products

// Custom naming
JauntyConfig.TableNameResolver = type => $"tbl_{type.Name.ToLower()}";
JauntyConfig.ColumnNameResolver = propertyName => $"col_{propertyName.ToLower()}";

Resetting Configuration

// Reset all configuration to defaults
JauntyConfig.Reset();

Note

Configuration should be set at application startup before executing any queries. Metadata is cached when a type is first used and won't pick up resolver changes afterward.

Naming Conventions

Jaunty provides built-in naming convention helpers through the NamingConvention class.

Available Conventions

public static class NamingConvention
{
    // Convert PascalCase to snake_case
    public static string ToSnakeCase(string propertyName);
    
    // Convert to lowercase
    public static string ToLowerCase(string propertyName);
    
    // Pluralize English words
    public static string Pluralize(string singular);
    
    // Combine snake_case and pluralization for table names
    public static string SnakeCasePluralTable(Type type);
    
    // Convert to snake_case for column names
    public static string SnakeCaseColumn(string propertyName);
}

Usage Examples

// Snake case conversion
NamingConvention.ToSnakeCase("ProductName");     // "product_name"
NamingConvention.ToSnakeCase("CustomerId");     // "customer_id"

// Pluralization
NamingConvention.Pluralize("Category");         // "Categories"
NamingConvention.Pluralize("Company");          // "Companies"

// Combined table naming
NamingConvention.SnakeCasePluralTable(typeof(Product));  // "products"
NamingConvention.SnakeCasePluralTable(typeof(Order));    // "orders"

Complete Configuration Example

// At application startup
JauntyConfig.ColumnNameResolver = NamingConvention.ToSnakeCase;
JauntyConfig.TableNameResolver = NamingConvention.SnakeCasePluralTable;

// Now property 'ProductName' maps to column 'product_name'
// And class 'Product' maps to table 'products'

Attribute Mapping

Jaunty provides attribute-based mapping for fine-grained control over how entities map to database tables and columns.

Available Attributes

[Table("table_name")]          // Specify table name
[Column("column_name")]        // Specify column name
[Ignore]                       // Ignore property during mapping

Table Attribute

[Table("order_items")]
public class OrderItem
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
}

Column Attribute

public class OrderItem
{
    [Column("item_id")]
    public int Id { get; set; }

    [Column("product_name")]
    public string Name { get; set; }

    [Column("unit_price")]
    public decimal Price { get; set; }
}

Ignore Attribute

public class Product
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }

    [Ignore]  // Not mapped from database
    public decimal CalculatedDiscount { get; set; }
}

Attribute Priority Order

  1. [Column] attribute
  2. JauntyConfig.ColumnNameResolver
  3. Property name (default)

Complete Attribute Example

[Table("order_items")]
public class OrderItem
{
    [Column("item_id")]
    public int Id { get; set; }

    [Column("product_name")]
    public string Name { get; set; }

    [Column("unit_price")]
    public decimal Price { get; set; }

    [Ignore]  // Not mapped from database
    public decimal CalculatedDiscount { get; set; }
}

// SQL uses database column names
var items = connection.QueryPartial<OrderItem>(
    "SELECT item_id, product_name, unit_price FROM order_items");

Command Options

CommandOptions provides a unified way to pass transaction and timeout settings without method overloading confusion.

CommandOptions<T> Structure

public readonly struct CommandOptions<T>(
    Func<IDataReader, T>? mapper = null,
    IDbTransaction? transaction = null,
    int? commandTimeout = null)
{
    public readonly Func<IDataReader, T>? Mapper = mapper;
    public readonly IDbTransaction? Transaction = transaction;
    public readonly int? CommandTimeout = commandTimeout;
}

CommandOptions (non-generic) Structure

public readonly struct CommandOptions(
    IDbTransaction? transaction = null,
    int? commandTimeout = null)
{
    public readonly IDbTransaction? Transaction = transaction;
    public readonly int? CommandTimeout = commandTimeout;
}

Static Factory Methods

// For CommandOptions<T>
CommandOptions<T> CommandOptions<T>.WithMapper(Func<IDataReader, T> mapper)
CommandOptions<T> CommandOptions<T>.WithTransaction(IDbTransaction transaction)
CommandOptions<T> CommandOptions<T>.WithTimeout(int seconds)
CommandOptions<T> CommandOptions<T>.With(Func<IDataReader, T> mapper, IDbTransaction transaction, int timeoutSeconds)

// For CommandOptions
CommandOptions CommandOptions.WithTransaction(IDbTransaction transaction)
CommandOptions CommandOptions.WithTimeout(int seconds)
CommandOptions CommandOptions.With(IDbTransaction transaction, int timeoutSeconds)

Usage Examples

// Timeout only
var products = connection.Query<Product>(
    "SELECT * FROM products",
    CommandOptions.WithTimeout(30));

// Transaction only
using var transaction = connection.BeginTransaction();
var products = connection.Query<Product>(
    "SELECT * FROM products",
    CommandOptions.WithTransaction(transaction));

// Both
var products = connection.Query<Product>(
    "SELECT * FROM products",
    CommandOptions.With(transaction, timeoutSeconds: 30));

// Custom mapper
var customMapped = connection.Query<Product>(
    "SELECT * FROM products",
    CommandOptions<Product>.WithMapper(reader => new Product
    {
        Id = reader.GetInt32("id"),
        Name = reader.IsDBNull("name") ? null : reader.GetString("name"),
        Price = reader.GetDecimal("price")
    }));

Best Practices

1. Configure at Startup

Always configure Jaunty at application startup before executing any queries. Configuration changes after the first query on a type will not take effect.

// DO: Configure at startup
public void ConfigureServices(IServiceCollection services)
{
    // Configure Jaunty
    JauntyConfig.ColumnNameResolver = NamingConvention.ToSnakeCase;
    JauntyConfig.TableNameResolver = NamingConvention.SnakeCasePluralTable;
    
    // Register other services
    services.AddScoped<IProductService, ProductService>();
}

2. Use Strict Mapping by Default

Take advantage of strict mapping to catch bugs early. Use QueryPartial<T> only when you intentionally want partial data.

// PREFER: Strict mapping for complete entities
var products = connection.Query<Product>(
    "SELECT id AS Id, name AS Name, price AS Price FROM products");

// USE: Partial mapping when intentionally selecting subset
var summaries = connection.QueryPartial<ProductSummary>(
    "SELECT id AS Id, name AS Name FROM products");

3. Leverage Attributes for Complex Mappings

Use attributes for one-off customizations rather than global configuration.

[Table("legacy_products")]
public class Product
{
    [Column("prod_id")]
    public int Id { get; set; }

    [Column("prod_name")]
    public string Name { get; set; }

    [Column("unit_cost")]
    public decimal Price { get; set; }
}

4. Use CommandOptions for Cross-Cutting Concerns

Use CommandOptions for transaction and timeout management rather than separate parameters.

// PREFER: CommandOptions
using var transaction = connection.BeginTransaction();
var products = connection.Query<Product>(
    "SELECT * FROM products WHERE category_id = @CategoryId",
    new { CategoryId = 1 },
    CommandOptions.With(transaction, timeoutSeconds: 30));

// AVOID: Separate parameters would require many overloads
// var products = connection.Query(transaction, timeout, sql, parameters); // Too many combinations!

5. Handle NULL Values Appropriately

Use nullable types for columns that might be NULL in the database.

public class Product
{
    public int Id { get; set; }           // Non-nullable: will throw if DB returns NULL
    public string Name { get; set; }      // Reference type: NULL becomes null
    public int? CategoryId { get; set; }  // Nullable: NULL becomes null
    public DateTime? DiscontinuedDate { get; set; }  // Nullable: NULL becomes null
}

6. Use Streaming for Large Result Sets

Use streaming methods when dealing with large datasets to avoid memory issues.

// FOR LARGE DATASETS: Use streaming
var products = connection.QueryStream<Product>(
    "SELECT * FROM products WHERE category_id = @CategoryId",
    new { CategoryId = 1 });

foreach (var product in products)
{
    ProcessProduct(product); // Process one at a time
}
