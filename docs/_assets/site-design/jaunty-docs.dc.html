API Reference / Insert

Insert<T>

extension method IDbConnection since 1.0

Inserts entity as a new row and returns the inserted entity with database-generated values populated. Jaunty emits an OUTPUT (SQL Server) or RETURNING (PostgreSQL) clause, so identity keys, defaults, and computed columns come back in a single round trip.

public static T Insert<T>(
    this IDbConnection connection,
    T entity,
    IDbTransaction transaction = null,
    int? commandTimeout = null
);

Parameters

entity T The object to insert. Identity / db-generated members are ignored on write and populated on return.
transaction IDbTransaction Optional transaction to enlist in. Defaults to null.
commandTimeout int? Command timeout in seconds. Defaults to the provider's timeout.

Returns

T — a new instance materialized from the row the database actually wrote, including generated keys, DEFAULT values, and timestamps.

Example

{{ copyALabel }}
using Jaunty;

using var connection = new SqlConnection(connectionString);

var order = new Order {
    CustomerId = 42,
    Status     = OrderStatus.Pending
};

// INSERT … OUTPUT INSERTED.* — generated values
// come back populated on the returned object
var created = connection.Insert(order);

Console.WriteLine(created.Id);        // 1087
Console.WriteLine(created.CreatedAt); // 2026-07-04 09:14
Entity requirements {{ expAChev }}
· One member marked [Key], or a member named Id by convention.
· Table name = pluralized class name; override with [Table("…")].
· Map columns with [Column("…")]; exclude with [NotMapped].
· Target a different database (SQL Server) with [Database("…")].

Insert

Write a row, get the truth back. Insert returns the entity exactly as the database stored it — identity keys, defaults, computed columns — in one round trip, courtesy of OUTPUT and RETURNING.

public static T Insert<T>(this IDbConnection connection, T entity,
    IDbTransaction transaction = null, int? commandTimeout = null);

Parameters

entity
T · required
The object to insert. Members backed by generated columns are skipped on write and filled in on the returned copy.
transaction
IDbTransaction · optional
Transaction to enlist in, if any.
commandTimeout
int? · optional
Seconds before the command times out; provider default when omitted.

Worked example

{{ copyCLabel }}

Install the provider for your database, then insert. The returned created object carries everything the database generated.

$ dotnet add package Jaunty.SqlClient
{{ copyICLabel }}
using Jaunty;

var order = new Order { CustomerId = 42, Status = OrderStatus.Pending };
var created = connection.Insert(order);

// created.Id        → 1087
// created.CreatedAt → 2026-07-04 09:14
A note on round trips
Because Jaunty leans on OUTPUT/RETURNING, there is no second SELECT SCOPE_IDENTITY() query — which is also why MySQL isn't supported.
