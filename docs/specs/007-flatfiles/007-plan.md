## 4. API Design

### 4.1 Opening and Querying a File Source

```csharp
// Simple — single CSV file
using var db = FlatFileDatabase.Open("sales.csv");
var results = await db.Query<SalesRecord>()
    .Where(x => x.Revenue > 10000)
    .OrderByDescending(x => x.Date)
    .Take(50)
    .ToListAsync();

// Configured — multiple sources
using var db = FlatFileDatabase.Open(options =>
{
    options.AddCsv<SalesRecord>("data/sales.csv", csv =>
    {
        csv.HasHeader = true;
        csv.Delimiter = ',';
        csv.NullString = "NA";
        csv.SkipRows = 2;
    });

    options.AddParquet<InventoryItem>("data/inventory.parquet");

    options.AddJson<CustomerProfile>("data/customers.json", json =>
    {
        json.Format = JsonFileFormat.NewlineDelimited;
    });

    options.PreloadIntoMemory = false; // VIEW by default
    options.PersistTo("cache.duckdb");  // Optional persistence
});
```

### 4.2 CRUD Against Flat Files

```csharp
using var db = FlatFileDatabase.Open("sales.csv");

// INSERT
await db.InsertAsync(new SalesRecord { Id = 999, Revenue = 50000, Date = DateTime.Today });

// UPDATE
await db.UpdateAsync<SalesRecord>(
    x => x.Id == 42,
    x => x.Revenue, 75000);

// DELETE
await db.DeleteAsync<SalesRecord>(x => x.Revenue < 100);

// Write back — non-destructive (new file)
await db.SaveAsync<SalesRecord>("sales-modified.csv");

// Write back — destructive (overwrite original)
await db.SaveAsync<SalesRecord>(WriteBackMode.Overwrite);

// Export to different format
await db.ExportAsync<SalesRecord>("sales-export.parquet");
```

### 4.3 Import Pipeline

```csharp
// Import CSV into SQLite
using var source = FlatFileDatabase.Open("sales.csv");
using var target = new JauntyDb(sqliteConnection);

await source.ImportIntoAsync<SalesRecord>(target, import =>
{
    import.BatchSize = 5000;
    import.OnConflict = ConflictStrategy.Upsert;
    import.CreateTableIfMissing = true;
    import.OnProgress = (imported, total) =>
        Console.WriteLine($"{imported}/{total} rows");
});

// Shorthand
await FlatFileImporter.ImportAsync<SalesRecord>("data/sales.csv", targetConnection);
```

## 5. DuckDB Dialect

| Responsibility | DuckDB Behavior |
|---|---|
| Parameter prefix | `$` (positional) |
| Identifier quoting | `"column_name"` (double quotes) |
| LIMIT/OFFSET | `LIMIT n OFFSET m` |
| Type mapping | C# → DuckDB: `string`→`VARCHAR`, `int`→`INTEGER`, `decimal`→`DECIMAL`, `DateTime`→`TIMESTAMP`, `bool`→`BOOLEAN` |
| Boolean literals | `true` / `false` |
| String concatenation | `\|\|` operator |
| File registration | `CREATE VIEW <name> AS SELECT * FROM read_csv_auto(...)` |
| Preload mode | `CREATE TABLE <name> AS SELECT * FROM read_csv_auto(...)` |

### File Registration SQL

```sql
-- CSV with auto-detection
CREATE VIEW sales AS SELECT * FROM read_csv_auto('data/sales.csv');

-- CSV with explicit options
CREATE VIEW sales AS SELECT * FROM read_csv_auto('data/sales.csv',
    header=true, delim=',', nullstr='NA', skip=2);

-- Parquet
CREATE VIEW inventory AS SELECT * FROM read_parquet('data/inventory.parquet');

-- JSON (newline-delimited)
CREATE VIEW customers AS SELECT * FROM read_json_auto('data/customers.json',
    format='newline_delimited');

-- TSV (explicit tab delimiter)
CREATE VIEW logs AS SELECT * FROM read_csv_auto('data/logs.tsv', delim='\t');
```

### Write-Back SQL

```sql
-- Export to CSV
COPY (SELECT * FROM sales) TO 'sales-modified.csv' (HEADER, DELIMITER ',');

-- Export to Parquet
COPY (SELECT * FROM sales) TO 'sales-export.parquet' (FORMAT PARQUET);

-- Export to JSON
COPY (SELECT * FROM sales) TO 'sales-export.json' (FORMAT JSON, ARRAY true);
```

## 6. CRUD Implementation Strategy

DuckDB operates on in-memory or file-backed tables. The CRUD flow:

1. **On Open**: File is loaded as a VIEW (lazy) or TABLE (preloaded)
2. **For CRUD**: If source is a VIEW, it's automatically promoted to a TABLE (DuckDB can't UPDATE a VIEW over `read_csv_auto`)
3. **INSERT/UPDATE/DELETE**: Standard DuckDB SQL via the dialect
4. **SaveAsync**: Uses `COPY TO` to write the modified TABLE back to a file
5. **Destructive mode**: Writes to temp file, then atomically replaces original (rename)
6. **Non-destructive mode**: Writes to the specified output path

### Table Promotion Logic

```
Open("sales.csv") → CREATE VIEW sales AS SELECT * FROM read_csv_auto(...)
                     (lazy, read-only queries work via VIEW)

First mutating operation (INSERT/UPDATE/DELETE) →
    DROP VIEW sales;
    CREATE TABLE sales AS SELECT * FROM read_csv_auto(...);
    (now DuckDB has a mutable in-memory copy)

Subsequent mutations → standard INSERT/UPDATE/DELETE on the TABLE

SaveAsync() → COPY (SELECT * FROM sales) TO '...' (FORMAT ...)
```

## 7. Import Pipeline Architecture

```
Source File (CSV/Parquet/JSON)
    │
    ▼
DuckDB (read_csv_auto / read_parquet / read_json_auto)
    │
    ▼
Jaunty Entity Mapping (validate schema, map columns)
    │
    ├── SQLite target → Batched INSERT via DbCommand (SQLite has no bulk API)
    ├── PostgreSQL target → Npgsql COPY binary protocol
    └── SQL Server target → SqlBulkCopy
    │
    ▼
Target Database Table
```

The pipeline reads from DuckDB in configurable batches, maps through Jaunty's entity metadata, and writes using the most efficient mechanism for each target.

## 8. Risks & Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| DuckDB.NET ADO.NET quirks | Medium | Milestone 1 surfaces these early; adapter layer if needed |
| DuckDB native binary size (~30MB) | Low | Document clearly; platform-specific packages available |
| Schema inference mismatches | Medium | Validate inferred schema against entity at registration; explicit overrides |
| Large file memory on TABLE promotion | Medium | Warn on promotion; document memory implications |
| Concurrent access to flat files | Medium | Document single-writer constraint; use temp-file-then-rename for writes |
| DuckDB.NET NativeAOT compatibility | Low | Isolated to engine package; doesn't block abstractions |

## 10. Future Considerations (Post v1)

- **Glob patterns**: `read_csv_auto('data/*.csv')` for multi-file sources
- **Cloud storage**: DuckDB's httpfs extension for S3/HTTP sources
- **Cross-source JOINs**: Fluent API support for joining across file sources
- **Streaming/append**: Watch directories for new files and auto-ingest
- **ATTACH**: DuckDB can ATTACH SQLite/PostgreSQL directly for zero-copy import
- **Alternative engines**: `Jaunty.FlatFiles.Sqlite` using SQLite's CSV virtual table
