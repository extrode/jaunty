Single Result Methods

Methods that execute queries and return single entities from the result set

Home > Overview > Single Result Methods

Overview

Single result methods execute SQL queries and return a single entity from the result set. These methods provide different behaviors for handling empty result sets and multiple results:

  • First methods: Return the first result or throw/return default
  • Single methods: Expect exactly one result or throw/return default

First Result Methods

QueryFirst<T>(string sql)

Executes a query and returns the first entity from the result set. Throws an exception if the result set is empty.

public static T QueryFirst<T>(this IDbConnection connection, string sql) where T : new()

Parameters

Name Type Description
connection IDbConnection The database connection
sql string The SQL query to execute

Returns

T: The first entity of type T from the result set

Exceptions

  • InvalidOperationException: If the result set is empty

Example

var product = connection.QueryFirst<Product>("SELECT * FROM products WHERE category_id = 1 LIMIT 1");

QueryFirstOrDefault<T>(string sql)

Executes a query and returns the first entity from the result set or the default value if the result set is empty.

public static T? QueryFirstOrDefault<T>(this IDbConnection connection, string sql) where T : new()

Parameters

Name Type Description
connection IDbConnection The database connection
sql string The SQL query to execute

Returns

T?: The first entity of type T from the result set, or null if the result set is empty

Example

var product = connection.QueryFirstOrDefault<Product>("SELECT * FROM products WHERE product_id = 999");
// Returns null if no product with ID 999 exists

QuerySingle<T>(string sql)

Executes a query and returns the single entity from the result set. Throws an exception if the result set is empty or contains more than one element.

public static T QuerySingle<T>(this IDbConnection connection, string sql) where T : new()

Parameters

Name Type Description
connection IDbConnection The database connection
sql string The SQL query to execute

Returns

T: The single entity of type T from the result set

Exceptions

  • InvalidOperationException: If the result set is empty
  • InvalidOperationException: If the result set contains more than one element

Example

var product = connection.QuerySingle<Product>("SELECT * FROM products WHERE product_id = 1");
// Expects exactly one result - throws if 0 or more than 1 results

QuerySingleOrDefault<T>(string sql)

Executes a query and returns the single entity from the result set or the default value if the result set is empty. Throws an exception if the result set contains more than one element.

public static T? QuerySingleOrDefault<T>(this IDbConnection connection, string sql) where T : new()

Parameters

Name Type Description
connection IDbConnection The database connection
sql string The SQL query to execute

Returns

T?: The single entity of type T from the result set, or null if the result set is empty

Exceptions

  • InvalidOperationException: If the result set contains more than one element

Example

var product = connection.QuerySingleOrDefault<Product>("SELECT * FROM products WHERE product_id = 1");
// Returns the product if found, null if not found, or throws if multiple products match

Single Result Methods with Command Options

Executes a query with command options and returns the first entity from the result set. Throws an exception if the result set is empty.

public static T QueryFirst<T>(this IDbConnection connection, string sql, CommandOptions<T> options) where T : new()

Parameters

Name Type Description
connection IDbConnection The database connection
sql string The SQL query to execute
options CommandOptions<T> Command options (transaction, timeout, custom mapper)

Returns

T: The first entity of type T from the result set

Example

    "SELECT * FROM products WHERE category_id = 1 LIMIT 1", 
    CommandOptions<Product>.WithTransaction(transaction));

Partial Mapping Variants

Jaunty also provides partial mapping variants of single result methods that only map properties with matching columns in the result set.

  • QueryPartialFirst<T>() - Returns first result with partial mapping
  • QueryPartialFirstOrDefault<T>() - Returns first result or default with partial mapping
  • QueryPartialSingle<T>() - Returns single result with partial mapping
  • QueryPartialSingleOrDefault<T>() - Returns single result or default with partial mapping
  • Async variants of all the above methods

Best Practices

Choose the Right Method

  • Use QueryFirst when you expect at least one result and only need the first one
  • Use QueryFirstOrDefault when you're OK with no results and only need the first one
  • Use QuerySingle when you expect exactly one result
  • Use QuerySingleOrDefault when you expect zero or one result

Handle Expected vs Unexpected Results

Use the appropriate method based on your expectations:

// When you expect a user to exist and it's an error if not found
var user = connection.QuerySingle<User>("SELECT * FROM users WHERE id = @Id", new { Id = userId });

// When it's OK if no user exists
var user = connection.QueryFirstOrDefault<User>("SELECT * FROM users WHERE email = @Email", new { Email = email });
